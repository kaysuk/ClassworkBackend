# Задание 8: Портфолио-сайт с использованием фреймворка

## Описание

Проект Ex8 был рефакторирован для использования архитектуры MVC фреймворка Initlab 2.0. Портфолио-сайт Drupal-coder теперь работает через единую точку входа с использованием URL-маршрутизации и модульной архитектуры.

## Архитектура решения

### 1. Точка входа (index.php)
- Главный файл приложения
- Обрабатывает все HTTP-запросы
- Создает объект `$request` с данными о запросе (URL, метод, GET/POST параметры)
- Вызывает диспетчер `init()` для обработки запроса

### 2. Конфигурация (settings.php)
Содержит:
- **Основные параметры сайта**: имя сайта, кодировка, пути
- **Маршруты URL** ($urlconf) - регулярные выражения для маршрутизации запросов
- Примеры маршрутов:
  - `'' => ['module' => 'front']` - главная страница
  - `/^portfolio$/ => ['module' => 'portfolio']` - раздел портфолио
  - `/^about$/ => ['module' => 'about']` - страница "О нас"
  - `/^contact$/ => ['module' => 'contact']` - страница контактов

### 3. Диспетчер (scripts/init.php)
Front controller, который:
- Парсит входящий URL и методы HTTP
- Находит подходящий маршрут в $urlconf
- Выполняет аутентификацию (если требуется)
- Загружает соответствующий модуль
- Вызывает функцию обработчика (например, `front_get()`)
- Передает результат в шаблон
- Возвращает HTTP-ответ с заголовками и содержимым

**Функции диспетчера:**
- `init($request, $urlconf)` - основная функция маршрутизации
- `conf($key)` - получение параметра конфигурации
- `url($addr, $params)` - генерация URL
- `redirect($l)` - редирект
- `access_denied()` - возврат 403
- `not_found()` - возврат 404
- `theme($t, $c)` - загрузка шаблона

### 4. Модули (modules/front.php)
Содержат обработчики для различных HTTP методов:
- `front_get($request)` - обработка GET запроса
- `front_post($request)` - обработка POST запроса
- `front_put($request)` - обработка PUT запроса (если нужен)
- `front_delete($request)` - обработка DELETE запроса (если нужен)

**Модуль front.php:**
- Функция `front_get()` - возвращает HTML контент портфолио
- Функция `render_portfolio()` - генерирует основной контент сайта

Возвращаемые значения модулей:
- Строка HTML - передается в шаблон
- Массив с headers - для редиректов и ошибок
- NULL - запрос не обработан

### 5. Шаблоны (theme/page.tpl.php)
- Основной layout HTML страницы
- Использует переменную `$c['#content']['front']` для вывода контента модуля
- Включает:
  - Head с подключением CSS/JS
  - Vue.js modal шаблон для контактной формы
  - Body с выводом контента
  - Подключение JavaScript файлов слайдеров

## Преимущества архитектуры

1. **Разделение ответственности (SoC)**
   - Логика приложения отделена от представления
   - Каждый слой отвечает за свою задачу

2. **Переиспользуемость (DRY)**
   - Общие функции вынесены в диспетчер
   - Шаблоны переиспользуются для разных модулей

3. **Масштабируемость**
   - Легко добавлять новые маршруты
   - Легко добавлять новые модули

4. **Тестируемость**
   - Модули можно тестировать отдельно
   - Диспетчер легко мокировать

5. **Безопасность**
   - Централизованная аутентификация
   - Контролируемая маршрутизация

## Как расширить функциональность

### Добавить новый модуль

1. Создать файл `modules/новый_модуль.php` с функциями:
```php
<?php
function новый_модуль_get($request) {
  return 'HTML контент';
}

function новый_модуль_post($request) {
  // обработка POST
  return redirect('/новый_модуль');
}
```

2. Добавить маршрут в `settings.php`:
```php
'/^новый_модуль$/' => array('module' => 'новый_модуль'),
```

3. Готово! Страница будет доступна по URL `?q=новый_модуль`

### Добавить аутентификацию

В `settings.php` для маршрута:
```php
'/^admin/' => array(
  'module' => 'admin',
  'auth' => 'auth_basic'  // используется auth_basic.php модуль
),
```
