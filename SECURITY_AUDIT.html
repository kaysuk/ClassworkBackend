1. Защита от XSS (Cross-Site Scripting)

Уязвимость

XSS позволяет злоумышленнику вставить вредоносный JavaScript код на страницу, который выполнится в браузере пользователя.

Методы защиты

1.1 htmlspecialchars()

Преобразуем специальные HTML символы в их сущности при выводе пользовательских данных.

<?php echo htmlspecialchars($user['name']); ?>
<?php echo htmlspecialchars($_POST['bio']); ?>
<?php echo htmlspecialchars($app['email']); ?>

1.2 Валидация входных данных

Проверяем типы и форматы данных на бекэнде перед сохранением.

$rules = [
    'name' => [
        'pattern' => "/^[a-zA-Zа-яА-Я\s]{1,150}$/u",
        'allowed' => "Допустимо: буквы и пробелы"
    ]
];
if (!preg_match($rules['name']['pattern'], $data['name'])) {
    $errors[] = "Некорректное ФИО";
}

✅ Результат оценки: 2 балла

Полная защита от XSS атак через htmlspecialchars() и валидацию входных данных

2. Защита от Information Disclosure

Уязвимость

Утечка информации о структуре приложения, путях файлов, версиях ПО через сообщения об ошибках.

Методы защиты

2.1 Отключение вывода ошибок

ini_set('display_errors', 0);
ini_set('display_startup_errors', 0);
error_reporting(E_ALL);
ini_set('log_errors', 1);

2.2 Безопасные сообщения об ошибках

function login($login, $password) {
    $user = findUserByLogin($login);
    if (!$user) {
        // Не разглашаем: "Пользователь не найден"
        return ['success' => false, 'error' => 'Неверный логин или пароль'];
    }
}

✅ Результат оценки: 1 балл

Защита от раскрытия информации через скрытие деталей ошибок

3. Защита от SQL Injection

Уязвимость

SQL Injection позволяет злоумышленнику модифицировать SQL запросы путем вставки вредоносного кода.

Методы защиты

3.1 Подготовленные запросы (Prepared Statements)

// УЯЗВИМО ❌
$query = "SELECT * FROM users WHERE login = '" . $_POST['login'] . "'";

// ЗАЩИЩЕНО ✅
$stmt = $pdo->prepare("SELECT * FROM users WHERE login = ?");
$stmt->execute([$_POST['login']]);

3.2 Все запросы используют prepared statements

// INSERT
$stmt = $pdo->prepare("INSERT INTO applications (...) VALUES (?, ?, ?, ?)");
$stmt->execute([$name, $phone, $email, ...]);

// UPDATE
$stmt = $pdo->prepare("UPDATE applications SET ... WHERE id = ?");
$stmt->execute([...]);

// DELETE
$stmt = $pdo->prepare("DELETE FROM applications WHERE id = ?");
$stmt->execute([$appId]);

✅ Результат оценки: 2 балла

Полная защита от SQL Injection через подготовленные запросы во всем коде

4. Защита от CSRF (Cross-Site Request Forgery)

Уязвимость

CSRF позволяет злоумышленнику выполнить действия от имени пользователя без его ведома.

Методы защиты

4.1 Использование сессий

session_start();
if (!isLoggedIn()) {
    header("Location: login.php");
    exit;
}

4.2 POST методы для изменений

if ($action === 'edit' && $_SERVER['REQUEST_METHOD'] === 'POST') {
    // Обработка редактирования
}

4.3 HTTP-only и Secure флаги

session_set_cookie_params([
    'httponly' => true,      // Недоступна для JavaScript
    'secure' => true,        // Только HTTPS
    'samesite' => 'Strict'   // Только same-site запросы
]);

✅ Результат оценки: 2 балла

Защита от CSRF через сессии, POST методы и безопасные флаги cookies

5. Защита от Include и Upload

Уязвимость

LFI/RFI и Upload атаки позволяют включать/загружать произвольные файлы.

Методы защиты

5.1 Только явные require

// БЕЗОПАСНО ✅
require_once 'db.php';
require_once 'auth.php';

// УЯЗВИМО ❌ (не используется)
// include($_GET['page']);

5.2 Жестко заданные пути

$action = $_GET['action'] ?? 'list';
if ($action === 'edit') { ... }
if ($action === 'delete') { ... }
// Не используется dynamic include()

✅ Результат оценки: 1 балл

Защита от Include атак через явные require. Upload функция не реализована.
